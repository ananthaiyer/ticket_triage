# CLAUDE.md: IT Support Ticket Triage

## What this project is
A small, production-style pipeline that takes IT support tickets, cleans and validates them,
classifies each ticket by **category** and **urgency**, and suggests a first reply.
An LLM (Claude API) is compared against a simple scikit-learn baseline, and the service
runs as an API on Google Cloud Run.

The goal is a portfolio project: small in scope, but clean, tested, deployed and well explained.
Prefer simple, readable solutions over clever ones.

## Data
- All data is **synthetic** (generated by `scripts/generate_tickets.py`). Never use real personal or company data.
- Categories: `hardware`, `software`, `access`, `network`, `email`, `other`
- Urgency: `low`, `medium`, `high`
- `data/eval/eval_set.csv` is a hand-checked evaluation set. Never use it for training or prompt examples.

## Architecture (Medallion layers)
- `data/bronze/`: raw tickets exactly as generated/ingested (JSON lines)
- `data/silver/`: cleaned, validated, deduplicated tickets (Parquet)
- `data/gold/`: aggregated tables, e.g. tickets per category/urgency per day (Parquet)

## Tech stack
- Python 3.11, Polars for data processing, Parquet for storage
- scikit-learn for the baseline (TF-IDF + logistic regression)
- Anthropic Python SDK for the LLM classifier (default model: `claude-haiku-5-5`)
- FastAPI for the API, Docker for packaging, Render for hosting (free web service, Docker runtime, region Frankfurt, auto-deploy from GitHub)
- pytest for tests, ruff for linting, GitHub Actions for CI

## Project structure
```
src/triage/
  pipeline/      # bronze -> silver -> gold steps
  quality.py     # data quality checks
  baseline.py    # scikit-learn classifier
  llm.py         # Claude classifier + reply suggestion
  evaluate.py    # compares classifiers on the eval set
  api.py         # FastAPI app
scripts/         # one-off scripts (data generation, running the pipeline)
tests/
data/            # bronze/, silver/, gold/, eval/
reports/         # evaluation results (markdown + images)
```

## Commands
- Install: `python -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt`
- Run pipeline: `python scripts/run_pipeline.py`
- Evaluate: `python -m triage.evaluate`
- Tests: `pytest`
- Lint: `ruff check .`
- Run API locally: `uvicorn triage.api:app --reload`
- Build Docker image: `docker build -t ticket-triage .`
- Run Docker image: `docker run -p 8000:8000 -e ANTHROPIC_API_KEY=... -e SERVICE_API_KEY=... ticket-triage`

## Rules
- Every new function that contains logic gets at least one test. Run `pytest` and `ruff check .` before saying a task is done.
- Never hardcode secrets. The API key comes from the `ANTHROPIC_API_KEY` environment variable (Secret Manager in the cloud). Never commit `.env`.
- LLM calls: return structured output (JSON), validate it, retry at most twice on failure, and fall back to `category="other", urgency="medium"` with a logged warning instead of crashing.
- Log with the standard `logging` module in a structured way (one JSON object per line), not with `print`.
- Keep changes small and focused. Explain what you changed and why, and list anything you were unsure about.
- Ask before adding a new dependency.
- Do not change files in `data/eval/`.
